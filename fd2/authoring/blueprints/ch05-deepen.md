### 4.0 `index.md`

- **Title** `# Zorn's Lemma`.
- **Story (~180 words).** Some objects are built one piece at a time: an injection one pair at a time, a set of representatives one class at a time, a total order one comparison at a time. When the pieces can be listed, recursion finishes the job. When they cannot, as for the subsets of ℝ, "and so on" is not a proof. Zorn's lemma is the principle that replaces it: if partial objects can always be enlarged when unfinished, and a growing chain of them has a partial object above it, then an unfinishable, hence complete, object exists. The chapter states the lemma (it is equivalent to the axiom of choice of Chapter 3, and this volume proves only that it implies choice), turns it into one template, and uses the template to settle the question Section 3.4 left open: any two sets are comparable in size.
- **What you need.** *Logic and Proof*, Chapters 1–8: the rule ∃E (@fd1:def-rules-existential) and the catalogue (@fd1:exm-not-allowed-catalogue), in particular (N13). ### 4.1 Section 5.1: Chains and Zorn's Lemma (`01-chains-and-zorn.md`, new)

**Budget:** main line ≤ 4,500 (expected ~3,700). No folds planned; fold candidates if over: the "why each hypothesis" paragraph's third example (finite subsets of ℕ) and the remark on the all-chains form. Four Quick checks, two warnings, one remark.

**Opening (~110).** "Section 3.4 proved that injections both ways give a bijection, and left open whether, for any two sets, at least one injection exists. Section 4.3 ended with a question about partially ordered sets: if every chain has an upper bound, must there be a maximal element? One principle answers both questions. It states Zorn's lemma, which answers the second, explains why this volume does not prove it, and turns it into a method of proof, the maximality template, with two first uses. Section 5.2 uses the template to answer the first question."

**`## Matching two sets, one pair at a time` (hook, ~480).**
1. Given sets A and B, try to build an injection by matching: pick a₀ ∈ A and b₀ ∈ B and pair them; pick a₁ ∈ A ∖ {a₀}, b₁ ∈ B ∖ {b₀}; continue until one side is used up. If it is A, the pairs are an injection A → B; if B, the reversed pairs are an injection B → A.
2. For finite sets the process stops: each step uses one more element of each side (Section 2.5). For A = {1, 2, 3} and B = {x, y}: (1, x), (2, y), and B is used up; reversed, x ↦ 1, y ↦ 2 is an injection B → A.
3. For A = B = ℝ it does not. After one step for each natural number, the pairs used form a countable set of elements of A (the image of ℕ, @prp-countable-image), and ℝ is uncountable (@thm-reals-uncountable-decimal); so neither side is used up, and "continue until" has no last step. The words "and so on" stand in for a step that is never given, (N13) of @fd1:exm-not-allowed-catalogue. (The infinitely many unnamed choices are a second problem, the one of Section 3.2.)
4. What the attempt does get right, in italics as the section's thesis: *every unfinished matching can be enlarged by one pair, and a growing family of matchings, put together, is again a matching.* The rest of the section makes "growing family" exact and supplies the principle that turns these two facts into a finished matching. "We return to the matching in Section 5.2." (In-chapter pointer; no box needed.)

**`## Chains` (~650).**
1. Lead: in the hook, the matchings built so far are pairwise comparable under ⊆: of any two, one extends the other. That is the "growing family".
2. **`def-chain`** `[Chain]`: "Let \( (X, \preceq) \) be a partially ordered set. A subset \( C \subseteq X \) is a **chain** if **any two** elements of \( C \) are comparable: for all \( x, y \in C \), \( x \preceq y \) or \( y \preceq x \)." One sentence after: a chain is a subset on which ⪯ is total (@def-partial-order); in a total order every subset is a chain.
3. **Examples** (a short list). In (ℕ, ∣): {1, 2, 4, 8, …} = {2ⁿ : n ∈ ℕ} is a chain (2ᵐ ∣ 2ⁿ for m ≤ n); {2, 3} is not. In (𝒫({1, 2, 3}), ⊆): {∅, {2}, {2, 3}} is a chain. Degenerate: ∅ and every one-element set are chains, vacuously and by (PO1).
4. **Quick check** (weird examples, before the lemma). "Decide: (a) Is {{1}, {1, 2}, {3}} a chain in (𝒫({1, 2, 3}), ⊆)? (b) Is {0, 1, 5, 25} a chain in (ℕ, ∣)? (c) Is {3, 6, 0} one? (d) In (ℝ, ≤), which subsets are chains?" *Solution:* (a) No: {1, 2} and {3} are incomparable. (b) Yes: 1 divides everything, 5 ∣ 25, and every natural number divides 0 = 0·a. (c) Yes: 3 ∣ 6, 3 ∣ 0, 6 ∣ 0. (d) All of them, since ≤ is total.
5. Lead to the lemma: in the hook, two pairs from the union of a growing family of matchings each come from some matching, and the two matchings are comparable, so both pairs lie in the larger one. That is the whole trick, for any finite number of elements.
6. **`lem-chain-union`** `[Finitely Many Members of a Chain]`:
   "(a) Let \( C \) be a chain in a partially ordered set \( (X, \preceq) \), let \( n \ge 1 \) and \( x_1, \dots, x_n \in C \). Then some \( x_k \) satisfies \( x_j \preceq x_k \) for \( j = 1, \dots, n \).
   (b) Let \( \mathcal{P} \) be a set of sets, partially ordered by \( \subseteq \), and \( \mathcal{C} \subseteq \mathcal{P} \) a chain. Then \( C \subseteq \bigcup \mathcal{C} \) for every \( C \in \mathcal{C} \); and if \( n \ge 1 \) and \( z_1, \dots, z_n \in \bigcup \mathcal{C} \), then some single \( C \in \mathcal{C} \) contains all of \( z_1, \dots, z_n \)."
   One sentence before the statement: ⊆ is a partial order on any set of sets, by the argument of @exm-subset-order-not-total (each set in 𝒫 is a subset of ⋃𝒫, and a partial order restricted to a subset is one).
7. **Proof.** (a) Induction on n (@thm-induction with n₀ = 1). n = 1: k = 1 by (PO1). Step: let x_k be above x₁, …, x_n. Since C is a chain, x_{n+1} ⪯ x_k or x_k ⪯ x_{n+1}. In the first case x_k is above all n + 1; in the second, x_{n+1} is, by (PO3) for j ≤ n and (PO1) for j = n + 1. (b) The first claim is the definition of the union. For the second, induction on n (@thm-induction with n₀ = 1), as in (a); each step makes one use of ∃E, so no choice is involved. n = 1: z₁ ∈ C for some C ∈ 𝒞 (one ∃E). Step: some C' ∈ 𝒞 contains z₁, …, z_n; one ∃E gives C'' ∈ 𝒞 with z_{n+1} ∈ C''; since 𝒞 is a chain, C' ⊆ C'' or C'' ⊆ C', and the larger contains all n + 1. (No "n uses of ∃E": that is the 'and so on' that (N13) flags.)
8. **Quick check:** "(a) Is there a chain of subsets of ℕ, none of whose members contains both 0 and 1, whose union contains both? (b) Is there such a family that is not a chain?" *Solution:* (a) No: by @lem-chain-union (b) with n = 2, if 0 and 1 lie in the union of a chain, some member contains both. (b) Yes: {{0}, {1}} has union {0, 1}, and neither member contains both. That shows why "chain" matters.

**`## Zorn's lemma` (~800).**
1. Lead: Section 4.3's question (its closing remark): if every chain has an upper bound, is there a maximal element? Naive attempt, ≤ 90 words: "Start anywhere, at p₀. If p₀ is not maximal, there is p₁ ≻ p₀; if p₁ is not maximal, p₂ ≻ p₁; and so on. The p_n form a chain, which has an upper bound u; if u is not maximal, continue above u…" Each step is legitimate; the "and so on", again, never ends, since the chain p₀ ≺ p₁ ≺ ⋯ may have an upper bound that is again not maximal, and continuing past every such bound is no finite or ℕ-indexed process. (N13) again. The principle is stated as its own result.
2. **`thm-zorn`** `[Zorn's Lemma]`, statement exactly as binding rule 1.
3. **Its status** (one paragraph, ~140 words, no `.remark`): "We do not prove @thm-zorn. It cannot be proved from the rules of logic and the working rules for sets of Chapter 1 alone: it is equivalent to the axiom of choice (@ax-choice). One half of the equivalence, that Zorn's lemma implies the axiom of choice, is the first application below (@thm-choice-from-zorn). The other half, which builds a maximal element from a choice function, is proved in *Axiomatic Set Theory*, together with the other equivalents. As with the axiom, we use the lemma openly and cite it at each use." One-line history allowed (carries mathematics): "Zorn (1935) put it in this form, convenient for algebra."
4. **Why each hypothesis is needed** (~300). Three examples, each with one sentence of checking:
   - (ℕ, ≤): non-empty, total, no maximal element (n < n + 1). The chain ℕ has no upper bound, so the chain hypothesis fails.
   - The empty partially ordered set: every non-empty chain has an upper bound, vacuously, and there is no maximal element. "Non-empty" is needed.
   - The finite subsets of ℕ, ordered by ⊆: non-empty (∅), and no maximal element: for finite F, ℕ is not a subset of F, since a subset of a finite set is finite (@prp-subset-finite) and ℕ is infinite (@exm-hilbert-hotel); for m ∈ ℕ ∖ F, F ∪ {m} is finite (@prp-disjoint-union-count) and strictly larger. Zorn's lemma, read backwards, says some non-empty chain has no upper bound; here one is visible: {∅, {0}, {0, 1}, {0, 1, 2}, …}, since an upper bound would contain every natural number.
5. **Warning** `**Maximal, not greatest, and not unique.**` "Zorn's lemma produces **a** maximal element, by no formula, and says nothing about how many there are. By @prp-greatest-maximal a greatest element would be maximal, but the converse fails (@exm-maximal-not-greatest): in the applications below there are usually many maximal objects and no greatest one."
6. **Quick check:** "Let P = {{1}, {2}, {1, 3}} under ⊆. List the chains with at least two elements; check that every non-empty chain has an upper bound; name the maximal elements." *Solution:* the only one is {{1}, {1, 3}}, bounded by {1, 3}; one-element chains are bounded by their element. Maximal: {2} and {1, 3}. Two maximal elements, as the warning says; no greatest.
7. **Remark** `[Every chain, or every non-empty chain]` (≤ 70 words): "Some books ask for an upper bound of **every** chain, the empty one included. An upper bound of ∅ is any element of P (@def-order-bounds), so that form simply contains 'P ≠ ∅'. The two forms say the same thing."

**`## The maximality template` (~1,600).**
1. Lead (~80): Zorn's lemma is used in one pattern. The first use proves the half of the equivalence that this volume can prove.
2. **`thm-choice-from-zorn`** `[Zorn's Lemma Gives Choice]`: "Assume @thm-zorn. Let \( I \) be a set and \( (A_i)_{i \in I} \) a family of **non-empty** sets. Then there is a function \( c \colon I \to \bigcup_{i \in I} A_i \) with \( c(i) \in A_i \) for every \( i \in I \)." (One sentence after: this is the conclusion of @ax-choice, so the axiom follows from Zorn's lemma.)
3. **`[Scratch work]`** (≤ 20 lines). A choice function is built one index at a time, like the hook's matching. A **partial** choice function is a set of pairs (i, x) with x ∈ A_i and at most one pair for each i, that is, a graph (@def-function) defined on part of I. Order them by ⊆: a larger one agrees with a smaller one and is defined at more indices. Write U ≔ ⋃_{i∈I} A_i.

   | Givens | Goal |
   |---|---|
   | each A_i ≠ ∅ | c : I → U with c(i) ∈ A_i for all i |
   | P: the G ⊆ I × U with (C1) (i, x) ∈ G ⇒ x ∈ A_i, (C2) (i, x), (i, y) ∈ G ⇒ x = y; order ⊆ | Zorn's hypotheses: P ≠ ∅; each non-empty chain has an upper bound in P |
   | ∅ ∈ P; for a chain 𝒞, try ⋃𝒞: (C1) and (C2) mention at most two pairs (@lem-chain-union) | a maximal M is defined at every i ∈ I |
   | M maximal; suppose i₀ is missed | M ∪ {(i₀, x₀)} ∈ P, strictly larger: contradiction |

   "The last row is a proof by contradiction (@exm-method-choosing-the-form): a missed index gives a larger partial object. Choosing x₀ ∈ A_{i₀} is **one** use of ∃E, which Section 3.2 showed is always allowed; Zorn's lemma does the infinitely many."
4. **Proof.** Let U and P be as in the table; P ⊆ 𝒫(I × U) is a set, partially ordered by ⊆. *P is non-empty:* ∅ satisfies (C1) and (C2) vacuously. *Chains:* let 𝒞 ⊆ P be a non-empty chain and H ≔ ⋃𝒞 ⊆ I × U. If (i, x) ∈ H, it lies in some G ∈ 𝒞, so x ∈ A_i by (C1) for G. If (i, x), (i, y) ∈ H, some G ∈ 𝒞 contains both (@lem-chain-union (b), n = 2), so x = y by (C2) for G. So H ∈ P, and G ⊆ H for every G ∈ 𝒞: H is an upper bound. *Zorn:* by @thm-zorn, P has a maximal element M. *M is defined everywhere:* suppose some i₀ ∈ I has no pair (i₀, x) ∈ M. Since A_{i₀} ≠ ∅, take x₀ ∈ A_{i₀}, and let M' ≔ M ∪ {(i₀, x₀)}. M' satisfies (C1), and (C2): the only pair of M' with first coordinate i₀ is (i₀, x₀). So M' ∈ P, M ⊆ M' and M ≠ M' (as (i₀, x₀) ∉ M), contradicting the maximality of M. Hence for every i ∈ I there is a pair (i, x) ∈ M, and by (C2) exactly one. By @def-function, M is the graph of a function c : I → U (codomain U), and c(i) ∈ A_i by (C1).
5. Aftermath (two sentences): if I = ∅, then P = {∅} and the proof gives the empty function, correctly. Of the four steps, only the last is about choice functions; the first three are the same in every use.
6. **`exm-method-maximality`** `[Method: the maximality template]`.
   - **Template.** To show that a complete object exists: (1) **partial objects:** let P be the set of partial objects, those the complete ones are the finished case of, ordered by ⊆ (extension); check P ≠ ∅, usually by the empty or the given starting object. (2) **chains:** for a non-empty chain 𝒞 ⊆ P, show ⋃𝒞 ∈ P; each defining condition mentions finitely many elements, which lie in one member (@lem-chain-union). (3) **Zorn:** P has a maximal element M (@thm-zorn). (4) **complete:** suppose M is not complete; use the missing piece to build a strictly larger partial object, a contradiction.
   - **When to use it.** The object can be built piece by piece, each condition on it checks finitely many pieces at a time, and the pieces cannot be listed.
   - **The usual failure.** The union of a chain is not a partial object, because a condition mentions infinitely many pieces ("finite", "countable"); step (4) produces an object that is not strictly larger or not in P; and treating M as the greatest or the only complete object.
7. **`exm-zorn-representatives`** `[A set of representatives]`: "Let \( \sim \) be an equivalence relation on a set \( X \). Show that there is a set \( S \subseteq X \) that meets every equivalence class in exactly one element."
   - **`[Scratch work]`**, short (≤ 10 lines, no table): by the method of @exm-method-maximality, partial objects are sets meeting each class **at most** once; the condition "s ∼ t ⇒ s = t" mentions two elements; a missed class [x] gives a larger partial object S ∪ {x}, with no choice needed, since x is in hand.
   - *Solution.* Let P be the set of S ⊆ X such that for all s, t ∈ S, s ∼ t implies s = t; ordered by ⊆. ∅ ∈ P. For a non-empty chain 𝒞, two elements s, t of ⋃𝒞 lie in one member (@lem-chain-union (b)), so s ∼ t gives s = t: ⋃𝒞 ∈ P is an upper bound. By @thm-zorn take a maximal M. Suppose some class [x] (@def-equivalence-class) contains no element of M. Then x ∉ M, since x ∈ [x] by (Eq1). And M ∪ {x} ∈ P: for s, t ∈ M ∪ {x} with s ∼ t, if both lie in M then s = t; if s = x and t ∈ M, then t ∼ x by (Eq2), so t ∈ [x] ∩ M, which is impossible; the case t = x, s ∈ M is the same; and s = t = x is fine. So M ⊊ M ∪ {x} in P, contradicting maximality. Hence M meets every class, and by the defining condition of P in at most one element: S ≔ M works.
   - Aftermath (≤ 80 words): the axiom of choice gives the same set in one line, choosing one element from each class; the template's advantage shows when the pieces interact, as in Section 5.2. **`## Back to comparing sizes` (~800).**
1. Lead: recall the 3.4 question in one sentence (@def-card-le, @thm-schroder-bernstein) and the hook's two facts.
2. **`thm-cardinal-comparability`** `[Any Two Sets Are Comparable]`: "For all sets \( A \) and \( B \), \( \card{A} \le \card{B} \) or \( \card{B} \le \card{A} \)."
3. **Idea** (four lines, citing @exm-method-maximality): partial objects are partial matchings, relations G ⊆ A × B in which each element occurs in at most one pair; a chain's union is one, since the condition mentions two pairs; a maximal matching uses up A or B, since otherwise one more pair fits.
4. **Proof.** Let P be the set of G ⊆ A × B with (M1) (a, b), (a, b') ∈ G ⇒ b = b', (M2) (a, b), (a', b) ∈ G ⇒ a = a'; ordered by ⊆. ∅ ∈ P. For a non-empty chain 𝒞 ⊆ P, any two pairs of ⋃𝒞 lie in one member (@lem-chain-union (b)), so ⋃𝒞 satisfies (M1), (M2) and is an upper bound. By @thm-zorn take a maximal M. *M uses up a side:* suppose a₀ ∈ A is in no pair of M and b₀ ∈ B is in no pair of M. Then M ∪ {(a₀, b₀)} satisfies (M1) and (M2) (the new pair shares no coordinate with an old one) and is strictly larger, against maximality. So every a ∈ A occurs in M, or every b ∈ B does. *Case 1:* every a ∈ A occurs. By (M1) exactly once, so M is the graph of a function f : A → B (@def-function), injective by (M2): \( \card{A} \le \card{B} \). *Case 2:* every b ∈ B occurs. The inverse relation M⁻¹ = {(b, a) : (a, b) ∈ M} (@def-relation) is the graph of a function B → A by (M2), injective by (M1): \( \card{B} \le \card{A} \).
5. Aftermath (one sentence): the hook's "continue until one side is used up" is now step (4): a maximal matching cannot be continued, so a side is used up.
6. **`cor-cardinal-trichotomy`** `[Trichotomy for Sizes]`: "For all sets \( A \) and \( B \), exactly one of \( \card{A} < \card{B} \), \( \card{A} = \card{B} \), \( \card{B} < \card{A} \) holds." *Proof:* at least one: by @thm-cardinal-comparability, say \( \card{A} \le \card{B} \); then \( \card{A} = \card{B} \) or, by @def-card-le, \( \card{A} < \card{B} \); symmetrically. At most one: \( \card{A} < \card{B} \) excludes \( \card{A} = \card{B} \) by definition, and likewise \( \card{B} < \card{A} \), using that "equinumerous" is symmetric (@prp-equinumerous-properties); and \( \card{A} < \card{B} \) with \( \card{B} < \card{A} \) gives injections both ways, hence \( \card{A} = \card{B} \) by @thm-schroder-bernstein, a contradiction.
7. One sentence: comparability is itself equivalent to the axiom of choice (*Axiomatic Set Theory*); "this book needed choice for it, and no proof can avoid it."

**`## Extending a partial order` (~1,500, including the worked schedule and the third Quick check).**
1. **Motivation** (~180): a list of tasks with prerequisites (task u must come before task v) is a partial order once each task counts as before itself; a schedule is a total order containing it. Finite: pick a task with no unfinished prerequisite, repeat. **Worked schedule** (~250, added at S2 to keep 5.2 above the 2,500 floor): five tasks with four prerequisite pairs, the order they generate written as a set of pairs, two different schedules produced by the finite procedure, and a check that each schedule contains every pair; the point is that the schedule is not unique and the procedure needs a list. For an infinite set with no list, the template does it. The engine is one step: two incomparable elements can be made comparable without breaking anything.
2. **`lem-one-step-order-extension`** `[Adding One Comparison]`: "Let \( \preceq \) be a partial order on \( X \) and let \( a, b \in X \) be incomparable. Let
   \( R \coloneqq {\preceq} \cup \{ (x, y) \in X \times X : x \preceq a \text{ and } b \preceq y \} \).
   Then \( R \) is a partial order on \( X \), \( {\preceq} \subseteq R \), and \( (a, b) \in R \setminus {\preceq} \)." (A partial order is a relation, a subset of X × X (@def-relation), so ⊆ between orders makes sense.)
3. **Idea** (two sentences): R puts everything below a below everything above b. A new pair can only break antisymmetry or transitivity by producing b ⪯ a, which incomparability forbids.
4. **Proof.** Write "new" for pairs with x ⪯ a and b ⪯ y. (a, b) is new (a ⪯ a, b ⪯ b) and not in ⪯, as a, b are incomparable. (PO1): ⪯ ⊆ R. (PO2): let x R y and y R x. Both old: x = y by (PO2) for ⪯. If (x, y) is new and (y, x) old: b ⪯ y ⪯ x ⪯ a, so b ⪯ a by (PO3), impossible. (x, y) old and (y, x) new: b ⪯ x ⪯ y ⪯ a, impossible. Both new: b ⪯ x (from (y, x)) and x ⪯ a, so b ⪯ a, impossible. So only the first case occurs. (PO3): let x R y and y R z. Both old: x ⪯ z. (x, y) old, (y, z) new: x ⪯ y ⪯ a and b ⪯ z, so (x, z) is new. (x, y) new, (y, z) old: x ⪯ a and b ⪯ y ⪯ z, so (x, z) is new. Both new: x ⪯ a and b ⪯ z directly. In every case x R z.
5. **Quick check:** "Apply @lem-one-step-order-extension to ⊆ on 𝒫({1, 2}) with a = {1}, b = {2}. Which pairs does R add?" *Solution:* new pairs (x, y) need x ∈ {∅, {1}} and y ∈ {{2}, {1, 2}}; all but ({1}, {2}) are already in ⊆. So R = ⊆ ∪ {({1}, {2})}, the total order ∅, {1}, {2}, {1, 2}.
6. **`thm-order-extension`** `[Every Partial Order Extends to a Total Order]`: "Let \( \preceq \) be a partial order on a set \( X \). Then there is a total order \( T \) on \( X \) with \( {\preceq} \subseteq T \)." (fd2 says "total" for linear (@def-partial-order); one sentence notes that "linear order" is a common synonym.)
7. **Idea** (three lines, citing @exm-method-maximality): partial objects are the partial orders containing ⪯; a chain's union is one, since (PO2) mentions two pairs and (PO3) two; a maximal one is total by @lem-one-step-order-extension.
8. **Proof.** P = {R ⊆ X × X : R a partial order on X, ⪯ ⊆ R}, ordered by ⊆; ⪯ ∈ P. For a non-empty chain 𝒞, H ≔ ⋃𝒞 contains ⪯ (it contains a member), so (PO1) holds. If (x, y), (y, x) ∈ H, one member R₀ contains both (@lem-chain-union (b)), so x = y. If (x, y), (y, z) ∈ H, one member contains both, so (x, z) ∈ R₀ ⊆ H. So H ∈ P, an upper bound. By @thm-zorn take a maximal T. If T were not total, take a, b incomparable for T; @lem-one-step-order-extension gives a partial order R ⊋ T, and R ⊇ ⪯, so R ∈ P, against maximality. So T is total.
9. **`exm-divisibility-linear-extension`** `[A total order containing divisibility]`: "On ℕ, let \( x \sqsubseteq y \) mean: \( y = 0 \), or \( x \ne 0 \) and \( x \le y \). Show that \( \sqsubseteq \) is a total order on ℕ containing ∣, and that ≤ does not contain ∣." *Solution:* (PO1): if x = 0, y = x = 0; else x ≤ x. Total: if y = 0 then x ⊑ y; if x = 0 then y ⊑ x; if both are non-zero, ≤ is total. (PO2): if x ⊑ y and y ⊑ x and one of them is 0, say y = 0, then y ⊑ x with y = 0 forces x = 0 (the second alternative needs y ≠ 0); if both are non-zero, x ≤ y ≤ x. (PO3): let x ⊑ y ⊑ z. If z = 0, x ⊑ z. Otherwise y ≠ 0 and y ≤ z; then x ⊑ y with y ≠ 0 gives x ≠ 0 and x ≤ y; so x ≤ z and x ⊑ z. Contains ∣: let a ∣ b. If b = 0, a ⊑ b. If b ≠ 0, then a ≠ 0 (0 ∣ b means b = k·0 = 0), and b = ka with k ∈ ℤ, k > 0 since a, b > 0, so k ≥ 1 and b ≥ a: a ⊑ b. Finally 2 ∣ 0 but 2 ≤ 0 fails. - **C2** `[C2: Find the error]` (true conclusion). "Claim: any two sets are comparable. 'Proof': If A or B is empty, the empty function is an injection.
